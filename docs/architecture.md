# Architecture sketch (v0)

The goal of v0 is a machine that boots straight into a chat harness, where the
harness *is* the user interface: there is no app launcher, no taskbar, no desktop.
Apps are small HTML programs the model writes on demand, and system settings
(Wi-Fi, audio, power, brightness, services) are tools the model calls, with UI
built for them when it helps.

```
┌──────────────────────────────── VM / laptop ────────────────────────────────┐
│ Arch Linux (built with archiso)                                             │
│                                                                             │
│  tty1 autologin (user "os") ─► llmos-session                                │
│        │                                                                    │
│        ├─ Hyprland (when a GPU render node exists) — hidden substrate:      │
│        │   no bar, no gaps, no animations; workspace 1 = shell,             │
│        │   workspace 2+ = real windows (Chromium tabs the model opens)      │
│        └─ cage (fallback kiosk compositor, software rendering, any VM)      │
│                                                                             │
│  ┌──────────────── Chromium --kiosk http://127.0.0.1:8800 ───────────────┐  │
│  │ Shell UI: projects ▸ conversation ▸ app stage                         │  │
│  │   mini apps run in <iframe sandbox="allow-scripts"> (opaque origin)   │  │
│  │   and talk to the shell only over a transferred MessagePort:          │  │
│  │     webMcp.registerTool()  — the model can drive the app             │  │
│  │     os.call(tool, args)    — the app can call granted system tools   │  │
│  └───────────────────────────────▲───────────────────────────────────────┘  │
│                                  │ SSE events + JSON POSTs                   │
│  ┌───────────────────────────────┴───────────────────────────────────────┐  │
│  │ llmos shell daemon (Node, 127.0.0.1 only)                             │  │
│  │   agent loop (Claude Messages API, streaming, tool use)               │  │
│  │   tool registry with tiers: read │ change │ confirm                   │  │
│  │     system.*  — info, network, audio, display, power, services, shell │  │
│  │     windows.* — hyprctl: open url, list/focus/close windows           │  │
│  │     apps.*    — create/update/open/close/delete apps, call app tools  │  │
│  │   store: ~/.local/share/llmos/{projects,apps,audit.jsonl}             │  │
│  └───────────────────────────────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────────────────────────────┘
```

## Decisions for v0

| Area | v0 choice | Why | Later |
|---|---|---|---|
| Base OS | Arch, built with archiso from the stock `releng` profile plus an overlay | Same base as Omarchy, rolling, tiny diff to maintain | Installable image with btrfs + Snapper + Limine rollback |
| Compositor | Hyprland, locked down, with `cage` as a fallback | Hyprland gives us IPC (`hyprctl`) for window control; cage boots in any VM without 3D | Our own compositor (Smithay) if Hyprland gets in the way |
| UI | One Chromium kiosk window on a local daemon | Web is the fastest way to generate UI; Chrome is wanted anyway | A2UI-style native components for system panels |
| Apps | HTML documents generated by the model, sandboxed iframe, Web MCP tools | Borrowed from voicebox's mini apps | Shelf/catalogue, sharing, versioning |
| System control | Tools that wrap CLIs (`nmcli`, `wpctl`, `brightnessctl`, `systemctl`, `hyprctl`, ...) | Works today, easy to read in the audit log | One MCP server per subsystem over D-Bus (NetworkManager, PipeWire, BlueZ, UPower, UDisks2) |
| Safety | Tool tiers; `confirm` tools need a click in the shell; every call is appended to `audit.jsonl` | The model has root-equivalent power (passwordless sudo) | Polkit-scoped D-Bus calls, per-project permissions |
| LLM | Claude via the Anthropic API (key entered on first boot or passed via QEMU `fw_cfg`) | Cloud first | Local model for offline/fast paths |
| State | Live ISO, state in RAM | Fastest path to "boots and works" | Persistent home on a second disk, then the installer |

## Where the voicebox ideas went

- **Mini apps + Web MCP**: kept the idea and the `window.webMcp.registerTool()` shape.
  v0 uses a single sandboxed iframe with a MessagePort handshake (the shell checks
  `event.source`, enforces a 5 s timeout and 64 KiB result cap) instead of voicebox's
  double-iframe bridge. Moving to the double bridge is an isolated change in
  `shell/public/apps.js`.
- **System command bus**: replaced by model tool calls. The shell can still bind
  keys to actions later.
- **Agent factory / self-hosting**: not in v0. Step 4 of the plan adds a tool that
  edits this repo on the machine, rebuilds, and rolls back on failure.

## Tool tiers

- `read`: runs immediately (status, lists, scans).
- `change`: runs immediately, reversible changes (volume, brightness, open a window, create an app).
- `confirm`: the shell shows the exact call and waits for Allow/Deny (shell commands,
  power off/reboot, service changes, deleting apps, joining a network).

Mini apps can call system tools through `os.call()` only if the model granted those
tool names when it created the app, and `confirm` tools still prompt.

## Self-hosting path (step 4 preview)

1. Ship the shell inside the image at `/usr/lib/llmos/shell` (done in v0, read-only).
2. Add a `self.*` tool set: edit the shell source in a git worktree, run tests, restart
   the daemon on the new build, keep the old one to roll back to.
3. Snapshot the system (btrfs/Snapper) before package-level changes.
